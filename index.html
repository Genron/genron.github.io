01 / Profile

Complex problems. Clear systems.

My work sits somewhere between software engineering, architecture and problem solving. I care about making software work today without making tomorrow's work unnecessarily difficult.

I do not just want software to function. I want it to remain understandable.

Over the years I have worked on historically grown applications as well as greenfield systems. This combination taught me to appreciate both sides: knowing when to improve what already exists and knowing when a clean architectural boundary is worth introducing.

05 / Engineering

Quality is part of the architecture.

Architecture without feedback eventually becomes documentation. I prefer engineering practices that continuously verify whether the system still behaves according to its intended design.

MR

Code Review

Mandatory merge requests, protected main branches and technical discussion before changes become part of the shared system.

T

Automated Testing

JUnit, Mockito, Spock, TestFX and integration testing used to create confidence while changing complex systems.

A

Architectural Rules

ArchUnit makes architectural decisions executable, helping prevent boundaries from slowly disappearing as a codebase evolves.

CI

Continuous Integration

Jenkins, Maven, Gradle and automated builds provide fast feedback and keep the path from source code to verified software repeatable.

SQ

Code Quality

SonarQube, coverage and static analysis complement human review with continuous signals about the health of a system.

AI

AI-assisted Development

I follow AI-assisted software development closely and use AI deliberately as a supporting tool while keeping engineering judgement with the developer.
